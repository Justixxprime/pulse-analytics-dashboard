What it does

Every interaction was considered on purpose.

Charts that animate in

Bars grow up from zero, lines draw themselves stroke by stroke, and the donut gauge sweeps around, every time real data replaces a skeleton.

Instant table search

Type in the search bar and rows filter immediately, the same as-you-type approach as a command palette, no submit button anywhere.

Drag anything, anywhere

KPI cards, chart widgets, even the core dashboard layout — press-and-drag to reorder, built on touch events so it works the same on a phone as it does with a mouse.

Sidebar-first layout

Icons and labels, an active-page highlight, and a collapsible drawer on mobile, the layout every serious dashboard is built on.

Real loading states

KPI cards, charts, and tables all show shimmering skeletons while data "loads," nothing pops in empty and then suddenly fills.

Dark mode, everywhere

One switch repaints all four app pages plus this landing page, no flash on reload, remembered on your device.

Sort by more than one column

Click a column to sort by it, shift-click a second one to add it as a tiebreaker — status first, then total, without losing the first sort.

Real editing, not a mockup

Edit an order, a customer, a discount code — changes save to your browser and stick around on reload, not just a flash of "saved" that resets itself.

FAQ

Questions people ask

Is the data real?

No. Every number is realistic mock data defined right in the JavaScript, so the UI, animation, and layout can be judged on their own.

What are the charts built with?

Hand-written SVG and CSS, no Chart.js or similar library. See js/charts.js in the project files.

Can I reuse this for a real project?

Yes. Swap the mock arrays in each page's JS file for a real API call and the skeleton-to-content flow keeps working exactly the same way.
